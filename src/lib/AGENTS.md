- On loopgramchannel.com, Firebase authDomain = own host (`pickAuthDomain()`, auth-domain.ts); src/server.ts proxies /__/auth/* and /__/firebase/* to FIREBASE_AUTH_DOMAIN. Why: Google's picker shows the brand, not firebaseapp.com.
- Growth helpers (share tags, ?t= moments, watch history, up-next) are pure functions in growth.ts; watch history stays on-device (watch-history.ts). Why: tested in one place, zero server cost.
- Home feed, /shorts and the Shorts swipe player (post.$id.tsx) order posts via mixFeed() (feed-mix.ts): hourly seeded rounds, one post per group per round in a fresh random order, a round never starts with the previous round's last group; group = hidden post `mix` (hash of the source account, set on TikTok import, never shown) else 30-min batch. Why: TikTok-style variety with no SSR/hydration mismatch and no visible account names.
- Google SEO tags/sitemap built in seo.ts (tested). Why: one place for Google tags.
- The edge shield keys pages/data by build id (`edgeKey()` + `__BUILD_ID__`); the client reloads once on missing-chunk errors (chunk-reload.ts). Why: a deploy must never serve cached HTML pointing at removed page files.
- Server code reads Worker keys via `readEnv()`/`syncWorkerEnv()` (worker-env.ts), which create/fill process.env from the Cloudflare `env` each request. Why: keys must work even when process.env is missing or unpopulated on workerd.
- Home feed pages come from `getPostsPage` → `pagePosts()` (feed-page.ts): server mixes once, sends 20 per page, cursor "seed:offset" pins the hourly mix. Why: visitors download only what they scroll to, without repeats when the hour changes.
- Former Redis data lives in Cloudflare KV behind the same `redis([...])` helper (backend.server.ts): `env.KV` binding, else KV REST API. Why: no external Redis trips; callers unchanged.
